# 合规结论（白帽采集边界）— 2026-10-27 调研

## 结论先行：两个聚合站都不能自动化采集

### 1. 官公需情報ポータルサイト kkj.go.jp（中小企業庁系）
- **robots.txt（实测 2026-10-27）：`User-agent: * / Disallow: /`** — 全站禁止爬虫。
- 因此：KKJ 只能**人工浏览作目录索引**使用，禁止对 kkj.go.jp 做任何自动化抓取/定时采集。
- 本次仅通过浏览器人工打开其「発注機関へのリンク集」页面 1 次，本地解析该页得到机构目录（3,959 条）。这是一次性目录调研，不是、也不会变成对 KKJ 的日常采集。

### 2. エヌ・サーチ nsearch.jp（株式会社うるる运营的商业服务）
- **会員利用規約「本サービスの利用に関する禁止事項」明确禁止（原文）：**
  - 「システムクローラーやスクレーパー等の自動収集システムによる複製行為」
  - 「本サービスを通じて入手した情報を、複製、無断掲載、販売、配布、出版する等、内部利用の範囲を超えて使用する行為」
  - 「本サービス外で本サービス及び本サービス付随機能を商業目的で利用する行為」
- robots.txt 本身为 `Allow: /`（仅禁 /s3_web_resources/ 等），但**利用规约优先**：robots 允许 ≠ 规约允许，两者必须同时满足才可采集（AND 关系）→ 结论 **NG**。
- 因此：nsearch 只能人工浏览作交叉核对，禁止爬取其 /organizations、案件搜索等任何页面。本次只人工读取了其公开的発注機関一覧页首屏的上位机构（约 26 家），用于与 KKJ 目录做域名级交叉验证，没有批量抓取、没有翻页抓取。

### 3. 合法的日常采集对象 = 各发注机关的官方网站本身
- 日本各级政府机关网站普遍采用 **公共データ利用規約（第1.0版，デジタル庁，2024-07-05）/ 政府標準利用規約（第2.0版）**：与 CC BY 4.0 兼容，注明出处后可复制、转载、加工，**商用亦可**；数值数据、简单表格本身不受著作权保护。
  - 条件：①标注出处（机关名＋页面 URL＋利用规约名）；②加工后须注明「已编辑/加工」且不得冒充官方原文；③第三方享有著作权的内容、法令限制内容除外，须逐项确认。
- 但每个机关仍须**逐站核查三件套**后才能列入日常采集：
  1. 该站 robots.txt 是否 Disallow 目标路径（例：北海道庁 robots 仅禁 /kana/ /mobile/ /translate/，入札页面不在禁止内；東京都仅禁参数类路径与 press 旧年度等）；
  2. 该站サイトポリシー／利用規約是否为公共データ利用規約系，还是有单独的禁止自动化条款；
  3. 若公告在**電子入札システム**内（如調達ポータル、各県電子調達システム、共同利用システム），还要看该系统的利用規約——公开的「入札情報公開（PPI）」浏览部分与需要 IC 卡/登录的投标部分必须分开，只采集无需登录的公开公告部分，禁止绕过登录、验证码、访问限制。

## 白帽采集规则（定版，写进采集器）
0. **源头唯一原则**：公告数据只取自发注机关官方网站／官方系统这一最原始的官方源头。商业入札信息服务（聚合站）的信息经过二次加工，一律不作数据源——不采集、也不引用其摘录做核对，避免二次加工信息违背「源头真实」原则。（KKJ／nsearch 的一次性对象枚举只取机关名录，性质不同；公告内容永远回官方站取得。）
1. **先 robots，后抓取**：采集器启动时逐域名读取 robots.txt 并缓存 24h；Disallow 的路径直接跳过并登记为「手動確認対象」。
2. **先规约，后上线**：每个源头在清单里必须有 `terms_status` 字段（已确认公共数据规约系 / 有单独限制 / 未确认=不上线）。
3. **低频礼貌访问**：同一域名请求间隔 ≥1.5–2 秒（大站 ≥1 秒），只在每日固定时段跑 1 次增量；设置可识别的 User-Agent（研究/采集方名称），不伪装成普通浏览器绕过封锁。
4. **只取公告事实信息**：案件名、发注机关、公告日、締切/開札日、公告原文 URL、文件 URL。公告 PDF 是官方公示文件，可下载留存并标注出处；不整站镜像、不转载聚合站的加工数据（聚合站的案件数据库是其运营者的商业资产，禁止复制）。
5. **不碰**：登录后页面、CAPTCHA、入札参加申请/投标功能、被 robots 禁止的路径、明确禁止自动收集的站点（如 KKJ、nsearch 本身）。
6. **403/429 即停**：遇到封锁或限流立即停该域名当日任务，记录待人工处理，不换 UA/IP 重试绕过。
7. **可追溯**：每条采集记录保存 来源URL、采集时刻、原文快照哈希，便于标注出处与纠错删除。

## 聚合站的正确用法（本项目定位）
KKJ 与 nsearch 在本项目中只是**「目录的目录」**：提供「日本有哪些发注机关、其官方域名是什么」的线索。最终源头清单里的每一条，都必须回落到机关官方域名，并逐条验证其现行入札公告页面（见 02_classification 与验证结果）。

## 补充（2026-10-27 浏览器逐条核查 KKJ 利用规约后修订）：KKJ 有官方 API 通道

初版结论「KKJ 只能人工浏览」需要细化为两条通道分开判断：

- **网页抓取：仍然禁止。** robots.txt 全站 `Disallow: /`，不得对 kkj.go.jp 的网页（包括リンク集、検索画面）做自动化抓取。
- **官方検索 API：这是 KKJ 专门为自动获取而设的正规通道，可以用，但有条件。**
  - 依据：KKJ《検索 API ガイド》V1.1 说明该 API 就是为了让外部系统自动取得官公需信息而提供；利用规约第 3 节专设「APIの利用について」。
  - 接口：`https://www.kkj.go.jp/api/`（GET/POST 二选一），返回 XML。实测 2026-10-27 仍在运行、返回 2026 年当日公告数据。
  - 可用参数：`Query` / `Project_Name` / `Organization_Name`（三者至少其一）、`Count`（默认 10、上限 1000）、`LG_Code`（都道府县 JIS 代码，可多选）、`Category`（1 物品 / 2 工事 / 3 役務）、`Procedure_Type`、`Certification`、日期区间 `CFT_Issue_Date`（公告日）/ `Tender_Submission_Deadline` / `Opening_Tenders_Event` / `Period_End_Time`。
  - 返回字段含：件名、机关名、都道府县/市区町村代码与名称、公告日、入札開始日、開札日、公示種別、公告全文，以及 **`ExternalDocumentURI`（公告在发注机关官网站上的原始 URL）**——正好与我们源头清单的机关/框架信息对上。
  - **使用条件（利用规约第 3 节，须全部遵守）**：① 在使用 API 的网站/应用上注明使用了本门户 API，并设置指向本门户的链接；② 遵守其并发请求数限制，禁止从单一服务器持续大量访问（具体限制数值规约未公开，需邮件联系运营者确认）；③ 不得从违反法令或公序良俗的内容/网站使用；④ 违规时运营者可遮断或限制 API 访问。
  - 另有 **RSS** 通道（官方有 RSS 使用说明书），可作低频增量补充。
  - 运营主体日英差异：日文版页脚与联系渠道指向中小企業庁（官公需担当邮箱）；英文版写运营者为 EU-Japan Centre。合规判断与联系以**日文版**为准。
  - 首页免责要点（转述）：门户不保证收录全部公告；公告通常在机关公开后约 1 日才登记到门户——因此 **API 适合做「每日新公告的发现层」，但重要机关仍应以官网站直连核实为准**，这正是本项目建源头清单的意义。

### 据此修订后的日常采集架构（双通道）
- **通道 A（发现）**：每日以 `CFT_Issue_Date=当日` 调 KKJ API（低频、分页 ≤1000/次、遵守并发限制）拿到新公告及其官网站原始 URL，页面与产品上按规约注明 API 出处并回链门户。
- **通道 B（核实/补充）**：按源头清单直连各机关官网站（逐站 robots + 规约已确认者），补 API 未覆盖的公募、随意契約公示与各县共同利用系统内的公告。
- nsearch 的结论不变：禁止自动化采集，仅人工浏览交叉核对。
