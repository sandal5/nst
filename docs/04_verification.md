# 验证进度 / Verification

方法：`scripts/check_links.py`——逐域名先读 robots.txt（禁止即跳过登记），再以 ≥1.5 秒间隔、10 秒超时、无重试的方式请求一次目标 URL，记录状态码、跳转终点与页面标题。Gordon 已一次性总批准本项目清单内全部网站的此类验证访问（2026-10-27），验证按批以单进程批量执行，不逐站询问。

## 失效链接找现行页的方法（定版，2026-10-27 Gordon 指示）
旧链接失效绝大多数只是**栏目迁移或网站改版**，按以下顺序找现行页，不跳步：
1. **站内解决（优先、一律先做）**：回到该机关官网首页，沿站内导航／栏目结构／站内搜索找「入札・調達」栏目，逐级定位现行公告页。能在站内解决的，一律在站内解决。
2. **`site:` 限定搜索（站内解决不了时才用）**：用搜索引擎的高级搜索限定主域名，如 `site:pref.shimane.lg.jp 入札`，只取该官方域名内的结果。
3. **普通关键词搜索不用**：结果被商业站广告与二次加工信息污染，且违背源头唯一原则；商业站页面不得作为证据来源。

落库标准（2026-10-27 Gordon 补充）：站内找页时用「入札公告」「調達」等关键词定位；最终落库的必须是**最新公告页**——一般同时存在列表页与详情页，**两者都记录**：列表页作轮询端点，最新一条公告的详情页 URL、标题、公告日作鲜度证据一并入库。

## 另一目录源的机构清单规模评估（2026-10-27，浏览器只读，人工低频共读 3 页）
- 该目录源的机构一览自报总数 **9,569 个发注机关**，分页 `?page=N`，每页 30 个，共 **319 页**（末页 29 个，318×30+29=9,569，数字自洽；评估时实读第 1、2、319 页，未遇封锁/登录墙）。
- **总量口径核准**：KKJ 记录 3,959 + 该目录源记录 9,569 = **13,528 条**，用户所说「两站合计 12000+」在记录口径下成立。
- **但独立网站口径要小得多**：该目录源尾部机构多为下级单位（县出先机关、区役所、广域联合/事务组合等），末页 29 条中只有约 5 条登记了官网 URL，其余没有独立官网；且头部机构与 KKJ 高度重合（第 1 页全部官网域名均已在 KKJ 域名名单内，无新域名）。因此实际需要逐个验证的独立网站以 KKJ 的约 2,566 个域名为主体，该目录源独有且带 URL 的机构数需另行抽样估计（其全量清单因规约禁止自动化收集，不做批量抓取）。
