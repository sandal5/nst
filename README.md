# nst — 全日本入札情報源リスト＆合規採集フレームワーク

> 整理**完整、准确**的全日本政府采购（入札）公告信息源网站清单，并在此之上提供一套**合法、白帽**的日常公告采集框架。默认部署在 **Cloudflare Workers** 上。
>
> 这是一个**开源公益项目**：把「源头清单 + 采集框架」做成公共基础设施，让以后任何想了解入札信息的人，都可以直接拿去二次开发自己的平台，或接入自己的 agent 使用，而不必再从零开始踩一遍过期链接和不完整数据的坑。

日本全国の発注機関（国の機関・独立行政法人・都道府县・市区町村）が入札公告を公開する公式ページを網羅的に整理し、利用規約と robots.txt を尊重する「白帽」採集の仕組みを作るプロジェクトです。

---

## 目标 / Goal

1. **一份权威源头清单**：每个发注机关一行——正式名称、所属都道府县、层级、官方域名、当前有效的入札公告页面 URL（而非过期的旧链接）。
2. **一套页面框架分类**：按网站信息架构把公告页面归类（见下 P1–P7），每类对应一个可复用的采集模版。
3. **一个可部署的采集器**：Cloudflare Worker 定时（每日）按模版直连**机关官方网站**采集新公告，结构化存入 D1/KV，供检索与订阅。

## 为什么需要直连源头？（背景）

现有的聚合门户（以 KKJ 为代表）一直在尝试汇总全国公告，但数据质量始终不好，这正是本项目存在的理由：

- **链接大面积过期**：本项目实测，都道府县级目录链接 62 条中 53% 已失效或异常（404、旧域名停用、系统迁移未更新）；
- **时效滞后**：聚合门户的公告通常在机关公开后约 1 天才被登记（门户自身免责说明亦如此写）；
- **覆盖不保证完整**：门户明确不保证收录全部发注机关公告，部分字段长期未整备；
- **错漏难以纠正**：数据经聚合层转手后，机关名、日期、原始链接等字段出错时，使用者无从核对、也无法回溯修正。

聚合层做不好的根源在于：全国有数千个发注机关、各自的网站结构与电子調達系统都在不断变化，没有一份**逐站验证、持续维护的源头清单**，再好的聚合系统都会慢慢烂掉。本项目就补这一层：**先把源头做准、做全，并把验证方法与采集模版一并开源**，让数据质量可以被任何人复查和接力维护。

## 给二次开发者 / For builders & agents

- **直接用数据**：`data/` 下的 CSV 就是交付物——源头清单、域名名单、订正记录、验证结果，可直接导入你的数据库或喂给你的 agent；
- **用采集框架**：`worker/` 是可独立部署的 Cloudflare Worker（Cron+Queue+D1），fork 后导入你维护的源头清单即可跑自己的每日采集；`scripts/` 是同一逻辑的 Python 参考实现；
- **接口约定**：公告统一字段见下文；Worker 提供 `GET /api/sources`、`GET /api/notices?pref=&date=` 两个只读接口。后续计划提供 JSON 全量导出与 MCP server 接口，方便 agent 直接接入（见路线图）；
- **许可**：代码 MIT；数据为事实信息（机关名与 URL），公告内容本身的权利归各发注机关、按其站点规约（公共データ利用規約等）注明出处使用。

## 为什么不能直接爬两个聚合站？（合规结论，重要）

本项目的线索来自两个目录站，但调研结论是**它们本身都不能自动化采集**：

| 来源 | 结论 | 依据 |
|---|---|---|
| [官公需情報ポータルサイト kkj.go.jp](https://www.kkj.go.jp/s/?cal=1) | ⚠️ 网页禁止抓取（robots 全站 `Disallow: /`），但有**官方検索 API 与 RSS** 可按规约使用 | 利用规约第 3 节：使用 API 须注明出处并回链门户、限制并发、禁止单一服务器持续大量访问；API 实测（2026-10-27）仍在运行并返回当日公告 |
| [エヌ・サーチ nsearch.jp](https://nsearch.jp/organizations) | ❌ 禁止自动化采集，仅可人工浏览作交叉核对 | 会員利用規約「禁止事項」明文禁止「システムクローラーやスクレーパー等の自動収集システムによる複製行為」，且禁止将站内信息复制/转载到内部利用范围之外 |

因此本项目的合法路径是**双通道**：① 每日用 KKJ 官方 API 按公告日增量「发现」新公告（API 返回公告在机关官网站的原始 URL）；② 按源头清单直连各机关官方网站「核实/补充」。nsearch 仍只作人工交叉核对。日本各级机关网站普遍采用《公共データ利用規約（第1.0版）》（デジタル庁，与 CC BY 4.0 兼容）：注明出处即可复制、转载、加工，商用亦可——但每个源头上线前仍须逐站核查 robots.txt 与本站规约。详细规则见 [docs/01_compliance.md](docs/01_compliance.md)（采集器内置的 7 条白帽规则）。

## 页面框架分类 / Framework taxonomy

| 代码 | 类型 | 采集模版 |
|---|---|---|
| P1 | 入札情報一覧型（nyusatsu/bid 路径的列表页） | HTML 列表解析：标题/日期/详情・PDF 链接，按日期增量 |
| P2 | 調達情報型（chotatsu 路径，国・独法为主） | 同 P1，同一省厅多机关共用页时按机关名过滤 |
| P3 | 公告・公募掲示板型（kokuji/koubo） | 列表解析 + 公告 PDF 正文抽取 |
| P4 | 電子入札／電子調達システム型（調達ポータル GEPS、各县電子調達・共同利用システム、PPI 入札情報サービス） | 仅用其**公开**的入札情報公開检索部分，逐系统写 adapter；禁止登录/IC 卡区域 |
| P5 | 契約情報型（keiyaku，公告与结果混排） | 列表解析时区分「公告中 / 結果公表」 |
| P6 | 機関トップ／汎用ページ型（目录只给了首页，72%） | 不能直接采集：先人工沿站内导航定位真正的公告列表页，再归入 P1–P5 |
| P7 | PDF 直接リンク型 | 仅作单件样本，不作源头 |

其中 P4 的**共同利用システム**是效率关键：一个县级电子調達共同系统可覆盖该县数十个市町村（例：島根県電子調達共同利用システム、かながわ電子入札共同システム、東京都電子調達システム）。详见 [docs/02_classification.md](docs/02_classification.md)。

## 采集框架 / Cloudflare Worker

代码在 [`worker/`](worker/)，部署说明见 [docs/03_worker_deployment.md](docs/03_worker_deployment.md)。

**轮询对象是 13,528 个发注对象在各自官网站上的公告页**（KKJ 3,959 + nsearch 9,569，均只做一次性枚举、之后不再访问）。轮询按「端点」执行而非按对象：多个对象共用的公告页只抓一次，再按机关名归属公告。端点分 A/B/C 三层频率（日/3日/周，自适应升降），先用 ETag/哈希判变、未变不解析，失败按 1→3→7 天退避后转重新验证。详见 [docs/05_polling.md](docs/05_polling.md)。

```
Cron (每日 08:00 JST) ──► 按都道府县分片 ──► Queue（每片一个任务）
                                                    │ 每片一个 consumer 调用
                                                    ▼
                              逐源头： ① 查 robots.txt（KV 缓存 24h，禁止即跳过并登记）
                                      ② 规约未确认的源头不采集（terms_status 门禁）
                                      ③ 同域名 ≥2 秒间隔礼貌抓取，403/429 当日停该域名
                                      ④ 按框架模版 P1–P5 解析列表页（P4 走专用 adapter）
                                      ⑤ 公告事实字段写入 D1，去重键 = 标题+机关+原文URL
                                                    ▼
                              API： GET /api/sources ・ GET /api/notices?pref=&date=
```

统一公告字段：`案件名 / 发注机关 / 都道府县 / 层级 / 公告种别 / 公告日 / 申请締切 / 入札・開札日 / 原文URL / 附件URL / 出处标注 / 采集时刻 / 框架类型 / 源头ID`。

本地参考实现（Python）在 [`scripts/`](scripts/)：目录解析、域名/框架分类、robots 优先的链接验证器（分批、断点续跑）。本地调研环境：Python 3.12 venv + BeautifulSoup/httpx + Playwright（无头 Chromium）。
