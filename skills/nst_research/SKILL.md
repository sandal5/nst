# nst 源头调研与采集方法

本 skill 提炼自 nst 项目 2026-10-27 立项会话中 Gordon 的全部定版指示与纠正。做 nst 的任何调研、验证、回填、采集器开发前先读它。仓库 github.com/sandal5/nst，本地工作区 ~/workspace/jp-procurement/，本地 clone ~/workspace/nst-repo/。

## 项目定位

- nst 是开源公益项目，目标是整理完整准确的全日本入札公告源头网站清单与合规采集框架，默认部署在 Cloudflare Worker 上，供他人二次开发自己的平台或接入自己的 agent 使用。

- 立项原因是 KKJ 的数据质量差。采集必须绕开聚合层，直连各发注机关的官方源头，这是 KKJ 一直想做却没做好的事。

- 当前阶段是收集信息阶段。先做准源头清单与验证，再做平台功能。

- Gordon 本人已合规使用 KKJ API。不要再向他重复介绍 API 的存在与用法。

## 不可违背的原则

- 源头唯一原则。公告数据只取自发注机关官方网站与官方系统这一最原始的官方源头。

- 商业入札信息站一律不碰。商业站的信息经过二次加工，违背源头信息真实的原则，不作数据源，也不引用其摘录做核对。典型反例是某商业入札速报服务，曾因搜索引擎结果被误引一次，已全部清除。

- 仓库不写商业名称。本仓库全部文件不出现商业公司的名称与其产品名，引用与出处一律只用政府官方来源。商业站只以泛称提及，数据与代码里用中性代号 dir2。

- KKJ 与另一商业目录源只作一次性对象枚举。两站只访问一次，把全部发注对象枚举出来，合计 13,528 条记录。此后不再访问这两站，采集对象是这 13,528 个对象各自的官方网站。

- 枚举只取机关名录。公告内容永远回到官方站取得。

## 标准工作流

- 第一步找到目标站，第二步找到入札公告的准确地址。这一步是本阶段最难的一步，目录里的旧链接大面积过期。

- 第三步采样分析该页面的 web 信息架构，第四步记录，第五步按 docs/02 的 P1 到 P7 分类。

- 第六步按分类做分类采集器，采集器要能部署到 Cloudflare Worker。

- 第七步做指数退避轮询。很多入札公告几个月才发一次，静默端点要拉长轮询间隔，减少对目标站的压力。

## 找现行公告页的方法

- 旧链接失效绝大多数只是栏目迁移或网站改版。按顺序找现行页，不跳步。

- 第一优先是站内解决。回到该机关官网首页，沿站内导航、栏目结构与站内搜索找入札栏目。能在站内解决的一律在站内解决。

- 站内解决不了，第二步才用搜索引擎高级搜索，加 site: 限定目标网站主域名，只取该官方域名内的结果。

- 普通关键词搜索不用。结果被商业站广告污染，且违背源头唯一原则。岛根县一例就是用普通关键词搜索把商业站引进来的，是方法错误，不只是来源问题。

- 落库标准是最新公告页。站内找页时用入札公告、調達等关键词定位。发注机关一般同时有列表页与详情页，两者都记录，列表页作轮询端点，最新一条公告的详情页 URL、标题与公告日作鲜度证据。

## 合规核查

- 采集前先读利用规定，只用合法的白帽方式采集。完整结论在仓库 docs/01_compliance.md。

- kkj.go.jp 的 robots.txt 全站禁止抓取，但它提供官方检索 API 与 RSS 作为机器通道。网页抓取这条路不要走。

- 另一商业目录源的会员规约明文禁止用爬虫或抓取工具自动收集。它只能人工浏览作目录索引。

- 每个官方站上线采集前逐站核查三件套，robots.txt、利用规约、以及电子入札系统自身的规约。官厅站多为公共数据利用规约或 CC BY 兼容条款，但不能想当然。

- 访问要礼貌。同域名间隔至少 1.5 到 2 秒，用可识别的 User-Agent，遇到 403 或 429 立即停该域名当日任务，不换 UA 或 IP 绕过。

- 只取公告事实信息，案件名、发注机关、公告日、截止与开札日、公告原文 URL、文件 URL。不整站镜像，不碰登录后页面与验证码区域。

## 验证的做法

- 用 scripts/check_links.py 批量验证。逐域名先读 robots，禁止即跳过登记，再以至少 1.5 秒间隔、10 秒超时、无重试请求一次，记录状态码、跳转终点与页面标题。

- 验证结果落盘为 CSV。失效链接进回填队列，按上面的找现行页方法逐站处理。

- 已实测的量级参考。都道府县级 62 条里 53% 失效或异常，KKJ 清单 3,448 个唯一 URL 对应 2,566 个域名。目录数据默认不可信，逐条验证后再用。

## 数据模型与轮询机制

- 按端点轮询，不按对象轮询。多个对象共用一个公告页时只抓一次，再按机关名把公告归属到对象。

- 判变在解析之前。先用 ETag 与 Last-Modified 做条件请求，再比对正文 SHA-256 哈希，无变化只记心跳。

- 静默指数退避。端点按 A、B、C 三层定基础间隔，每次无变化间隔翻倍，直到该层上限，有变化立即重置回基础间隔。

- 失败也退避。连续失败按 1 天、3 天、7 天拉长，之后转重新验证状态，回去按找现行页方法重新找页面。

- robots 禁止、规约未确认、P6 未定页的端点一律跳过，永不抓取。

## 版本迭代规则

- 本 skill 按语义化版本迭代，版本号同时写在同目录 VERSION 文件与 skill.yaml 的 version 字段，两处必须一致。

- 每次修改 skill 内容，先在 CHANGELOG.md 的 Unreleased 段记一条。发布时把 Unreleased 段落改为新版本号加日期。

- 版本号进位规则。原则级变更或不兼容的方法改版进 major，新增方法或新定版事项进 minor，文字修正与证据补记进 patch。

- 修改流程是先改仓库 skills/nst_research/ 下的正本，再同步到 ~/workspace/custom-skills/nst_research/，最后随仓库一起 commit 并 push，commit 信息带版本号。
