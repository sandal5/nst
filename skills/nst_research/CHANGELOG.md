## [0.2.0] - 2026-10-27

### Added

- 仓库不写商业名称的规则（Gordon 当日定版）。全仓库不出现商业公司的名称与其产品名，引用与出处一律只用政府官方来源，商业站只以泛称提及，数据与代码里用中性代号 dir2。

### Changed

- 按新规则全仓库清除商业名称。README 许可与出处删去商业运营者，合规、验证、轮询文档与本 skill 正文改用泛称，数据 CSV 的来源标记列与脚本、Worker 注释同步改用中性代号 dir2。
- docs/05 里另一目录源枚举的状态据实更新为被来源站拦截、0 条、待以更慢的人工节奏重试。

## [0.1.0] - 2026-10-27

首个版本。内容全部提炼自 nst 项目 2026-10-27 立项当日的会话交互，包括 Gordon 的定版指示、两次方法纠正与一次来源事故的教训。

### Added

- 项目定位。公益开源、直连源头绕开聚合层、当前为收集信息阶段，以及不重复介绍 Gordon 已在用的 KKJ API。
- 源头唯一原则。公告数据只取最原始的官方源头，商业入札信息站一律不碰，含某商业服务被误引又清除的来由。
- KKJ 与另一目录源的一次性枚举定位。两站只枚举对象名录共 13,528 条，公告内容永远回官方站。
- 标准工作流七步。找目标站、找公告准确地址、采样分析 web 信息架构、记录、P1 到 P7 分类、分类采集器、指数退避轮询。
- 找现行公告页的方法定版。站内解决优先，站内不行才用 site: 主域名限定搜索，普通关键词搜索禁用。
- 合规核查要点。KKJ 网页抓取禁止与官方 API 通道，另一目录源规约禁止自动收集，逐站三件套核查，礼貌访问与 403/429 即停。
- 验证做法。check_links.py 的参数口径与已实测量级，都道府县级 53% 失效。
- 数据模型与轮询机制。按端点轮询、哈希判变、静默指数退避、失败退避转重新验证、未确认端点永不抓取。
- 与 Gordon 的协作方式。一次性总批准与批量执行，gh 加本地 git 推送，直接具体的报告风格，方法纠正要落文档并同步给执行中的 agent。
- 版本迭代规则本身。语义化版本、VERSION 与 skill.yaml 双写、变更先记 Unreleased、正本在仓库并同步到 custom-skills。
