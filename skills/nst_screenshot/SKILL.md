# nst 截图 + OCR 枚举与核验方法

本 skill 提炼自 nst 项目 2026-10-28 Gordon 的定版指示与同日试点的实测结论（试点报告 `output/screenshot_pilot/PILOT.md`，在 jp-procurement 工作区）。当 HTML 采集路线走不通或不被允许、而任务性质是「看一眼页面、把看得见的名录/状态记下来」时，用截图路线。仓库 github.com/sandal5/nst，本地工作区 ~/workspace/jp-procurement/，本地 clone ~/workspace/nst-repo/。

## 适用场景（只有两个）

- **一次性对象枚举**：某目录源只许人工浏览、不许爬虫收集时，按 Gordon 2026-10-28 的决定，改以「全页截图 + OCR」一次性把机关名录落表。此后不再访问该站，公告内容永远回各机关官方站取得（源头唯一原则不变，见 nst_research）。
- **robots 禁止页面的视觉核验**：robots 明文禁止自动抓取的主清单行，不爬 HTML，改截图看图确认——页面是否可达、是不是入札公告页、最新公告日期。截图核验只确认「页面存在与性质」，不批量摘录其内容。

不适用于：日常采集（走端点轮询 + 网关）、需要 href 的场景（截图拿不到链接目标，只能拿到页面上印出来的文字）。

## 环境

- Playwright（项目 venv）+ 系统 Chromium `/opt/meta-chromium/chrome`（executable_path 指定），viewport 1440px。
- Tesseract 5.x + 日文语言包（`apt-get install tesseract-ocr tesseract-ocr-jpn`），`jpn+eng`、PSM 6。
- PIL 拼接；httpx 作本地取页器。参考实现在 `scripts/`（capture.py / ocr.py / build_table.py，源自试点）。

## 取页通道（最关键的一节，先读）

目标站若在 AWS WAF 类防护后面，**从数据中心出口直连浏览器导航走不通**：浏览器 UA 会收到 202 空挑战页（挑战 token 端点在本出口超时、永不完成），换 UA 是 403 或挂死。实测同一出口下 httpx/curl 带浏览器 UA 同样 202 空、带默认（非浏览器）请求头则立即 200 全文。

工作路线：**Chromium 本身不直连目标**，全部请求由本地取页器经 Playwright route interception 履行：

- 取页器 = httpx，默认请求头，环境代理，跟随重定向；
- **每个请求新建 client**——持久 cookie 罐会把后续请求毒化进挑战路径；
- **请求串行化**（一把锁）——并行代理隧道会卡死；静态资源内存缓存（各页相同）；
- 追踪域名（googletagmanager、clarity、doubleclick 等）直接短路 204，否则每页烧 90 秒重试；
- 页面间 ≥3 秒、单主机串行，保持一次性枚举的低频礼貌。

注意：这条路线用非浏览器请求头取页，与「浏览器 UA」指示冲突是出口现实所迫，执行前要在报告里明示，不得默默绕过。

## 展开（截图前必做）

- 「この発注機関の下位の機関」类手风琴区块**初始 HTML 里是空的**，展开才加载；不展开就截图等于整层丢失。
- 下位机关本身是完整卡片（有自己的名称、件数、明文 URL），且可能再带下位区块——树深于一层。
- 做法：**循环「展开 → 等待 → 再扫描」，直到不再出现新的展开按钮**。试点第 1 页：30 个顶层卡展开后变 883 个卡、页面高 168,574px。

## 全页截图

- Playwright `full_page=True` 在超高页面上会把渲染器撑崩。改用 CDP `Page.captureScreenshot`（captureBeyondViewport）按 **6,000px 分片**截取，PIL 纵向拼成整页 PNG。
- 试点尺寸：1440 × 168,574（18 MB）/ 132,641 / 5,370。整轮存储预估数 GB 以内。

## OCR 与解析

- 整页按 **3,000px 横带**切分、**×2 放大**后逐带 OCR（TSV 输出，保留词坐标）；带间 **重叠 200px**，否则压在切带边界上的卡片会漏检（试点约 1% 漏检与此一致）。
- 解析按版式锚点切卡片；**层级靠 x 坐标判定**：1440px 宽下顶层名称行 x≈122、下位 x≈204，上级 = 最近的上一个顶层条目。
- 实测精度（试点 3 页、1,622 行，对 DOM 真值评分；真值只用于试点评分、不用于枚举数据）：
  - 条目检出率 98.9% / 99.3% / 100%；
  - 名称字符相似度 ≥0.9 的可恢复率 73.8% / 83.0% / 86.7%，抽查 20 个名称平均相似度 0.959、17 个全字精确；
  - **卡面 URL 是明文印出来的**（每张卡都印官方 URL 全文）：98–99% 被 OCR 捕成 URL 形字符串，但逐字精确率只有 54–81%。

## 落表标准（质量闸门）

- OCR 出的 URL 一律是**草稿**（url_status=draft_unverified）：入库前必须回官方渠道核定，这与「dir2 只供名录、官网地址回官方定」的项目规则一致。畸形主机名（丢点、l→I、数字字母互换）用语法校验可靠地标出来。
- 名称走后处理：系统性误认是固定几种——`庁`→`店`、`落`→`沙`（件数文字）、县名括号碎成尾巴垃圾（如 `…RRB)`）。用后缀词典（庁・局・大学・組合…）+ 置信阈值做归一化/标记：clean / normalized / low_confidence 三档，**低置信名称进人工队列，绝不静默通过**。
- 总数对账：落表行数必须和来源自报的总件数对得上（试点：323 页 = 322×30+9 = 9,669 件，与页眉自报一致）。对不上先查漏页/漏展开，不许凑数。

## robots 核验的边界

- 普通市町村站截图核验完全可行（试点広尾町：200、公告页一眼可辨、OCR 能读出标题与日期）。
- Akamai 类 CDN 的国家机关站会拒绝本基础设施的全部出口（VM 代理与项目网关都 403）——截图只能证明「从这里过不去」，**不能证明页面内容**；这类行标 blocked_cdn 留人工（需住宅网络视角），不重试硬冲。

## 节奏与耗时（全量参考）

- 323 页全量：截取串行约 3–5 小时（展开等待占大头），OCR 约 3.3 CPU 小时、多进程后 35–45 分钟，**整轮现实估计 2–4 小时墙钟**。必须逐页 checkpoint，崩溃最多丢一页。
- 单页耗时方差极大（首页 206 秒 vs 尾页 7 秒），按「页」报进度，不要按时间承诺。
